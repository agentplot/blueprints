# Assertion: the context map becomes a distributable tool

- **Repo:** agentplot/flywheel
- **State:** open
- **Raised by:** the operator, 2026-08-06

## The claim
The map application travels and accepts a map from outside itself — a CLI
fed JSON is the shape to design against. The book skills travel with it, so
the flywheel can do a writeback in a repo that has never seen
`books/CLAUDE.md`.

## Why
The tool is usable by anyone designing a system; the data describes Willdan
systems.
→ decisions/flywheel-repo-manifest.md
→ sessions/2026-08-06-flywheel-repo-split/context-map-tool.md · book-knowledge.md

## Boundaries
The maps stay in blueprints, and there are **three** of them — `current`,
`target`, `configurations` — the third with its own validation arm and
viewer tab. Generalizing is not a lift-and-shift: `context-map/schema.json`
carries Willdan's tier enum, the blueprints host in its `$id`, `^books/` in
three patterns, and a Geo IQ chapter in a description. Poach the book
knowledge from `system-design-inception` but fix its two defects rather than
copying them (→ assertions/marketplace-poach-defects.md).
