# Askers and surfaces

Every surface answers from one core, and the same question on any
surface gets the same answer (56). Every answer is readable by a
program on request, naming digests, versions, channels and verdicts as
the statement names them (57).

| surface | what it does |
|---|---|
| the command line | `push`, `attest`, `publish`, `verify`, `promote`, `sync`, `serve`, `status`, each with its answer as JSON on request |
| a Claude Code plugin | a hook that refuses an ecosystem's own publish command and names tailrace's; a skill over the verbs |
| a herdr plugin | a pane of channels and environments, the last refusals, and a publish's progress |
| a Flywheel plugin | an adapter that prints a capture for each publish and each refusal, which millpond lands once |

## Three answers, never one

A verdict says which: satisfied; refused, naming the first claim found
wanting and why; or unreadable, naming what could not be read (58).
tailrace never answers a refusal as an absence, an absence as a refusal,
or either as unknown. Where a store, a signer or an ecosystem refused,
its own words come verbatim beside tailrace's (59).

Asking what tailrace holds reaches no store, no signer and no target,
and writes nothing (60).

## What tailrace keeps

tailrace keeps only what the store cannot answer: which versions it
published from which revisions, which layouts it rendered under which
policy (61). Everything it keeps is readable with no tailrace process
running, from every checkout, by plain tools (62), and can be deleted,
apart from the record of versions claimed, and rebuilt from the store
and git (63). It keeps no credential (64).

The policy is read from the repository at a landed revision of the
branch it governs, never from a publisher's checkout (65), so a publish
cannot carry a policy that admits itself.
