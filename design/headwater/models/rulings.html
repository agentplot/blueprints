headwater Rulings

A fresh model, given only the statement, designed headwater and asked 32 questions where the statement was silent or contradicted itself. Each has a recommended ruling below, with one more on a word the statement shares with Flywheel. Once you rule, the rulings go into models/reconstruction-1-answers.md and into the statement as clauses, as sluice's did.

Repository, held state and answers

  1. 1What is "a repository": one clone, or every clone on every host?contradiction28 · 48 · 50 · C.6The checkouts that share one held state. Under the git-directory store that is one clone; sharing across hosts is a later store profile, as sluice's state refs are.Add repository to the vocabulary.
  2. 2Whose repository state does "what headwater holds" answer for, when checkouts sit at different commits?17 · 31 · 32The asker's own, applied to what the sources last said (the model's design). A dependency no scan has looked for yet is reported as not yet looked for.Rewrite 17; add the status to report.
  3. 3An answer also depends on the binding, the asker's credentials, the clock and headwater's version.32 · 38 · 45 · 51An answer depends on the repository state, the held state, the binding, the time and headwater's version, never on who asks. A failed lookup never erases what a source said before: the answer keeps the last listing and its time beside the failure.Rewrite 32; a new clause on failed lookups.
  4. 4Who binds the profiles, and where is the binding read from?51 · actorsThe repository's authors, in the repository beside the tiers, defaulting to every profile that recognises a declaration. Credentials stay the asker's.The authors' row gains "which sources to ask"; 51 says where.
  5. 28Do 29 and S9 assume the sources did not change between scans?11 · 29 · S9Yes: S9 compares against the same source answers. Notes are read again at each scan of a tier, so upstream's edits arrive.Rewrite 29 and S9 to hold for the same source answers.
  6. 29How are uncommitted changes named, and may a scan of a changed checkout write?31 · vocabularyA repository state is the checkout as it stands, committed or not, reported with its commit and whether it holds changes. It may write, since what it keeps is per dependency, never per state.Rewrite repository state.
  7. 31What does "as one or the other would have left it" mean for two scans at once?30 · 49As if one ran after the other: each lookup kept by its key, the later one winning, and acknowledgements untouched.Rewrite 30.

Pins and identity

  2. 6Which pin does an advisory have to name, and are advisories on newer releases given?18 · 4Affected when an advisory names any declared pin.   3. 7One identity per dependency, yet one tool can be pkg:cargo/x and pkg:github/o/x.contradiction2 · C.1 · S11The identity is the name the declaration's own ecosystem gives. Sources and what they say

  1. 12What counts as two sources disagreeing, and whose order wins?8 · 39 · 44 · 51A release one source lists and another does not yet is no disagreement: sources lag. Releases merge by identity, each carrying every source's account. Where two orders differ, the release is undecided with both.39 defines disagreeing.
  2. 13Does C.4's changelog-only-without-a-release-body choose between sources?39 · C.4No: the changelog declines where a release body exists, so only one source answers. A repository that binds both to answer always gets both, each named.39 says headwater never chooses between answers it received.
  3. 20Do the notes and advisory sources count toward a complete scan?15 · 16 · vocabularyRelease and advisory sources count; notes do not. A release with unread notes is still reported, and its notes are read again at the next scan or by a brief.Rewrite complete.
  4. 21The notes and advisory reads have no "could not be reached".46 · 47 · 18Add it to both. An unreached advisory source makes the advisory status unread, never "not affected".46, 47 and 18.
  5. 22Clause 8 leaves no room to hold back a prerelease, so both §10 options break it.contradiction8 · 43 · §10A report holds a newer prerelease only where the pin is a prerelease or the dependency's tier asks for them. Listings carry the source's own prerelease mark, else the version grammar's.Rewrite 8; 43 gains the mark.
  6. 23Is a withdrawn release one "the source publishes"?8 · 43Yes, with the source's withdrawn mark, on a newer release and on the pin alike. A withdrawn pin is a reason to move, so it shows.8 counts withdrawn releases, marked.
  7. 32Can "a source learns nothing but identities and versions" be checked, given batching and credentials?37 · actorsChecked on recorded requests in the conformance suite. Batching is allowed. The asker's own credentials identify the asker by the asker's choice, which is not something of the repository.37's details; a non-goal: hiding the asker from a source.

Tiers and cadence

  1. 14Every dependency description reads tiers, yet C.2 has one tiers file and the watch list a tier column.41 · 51 · B.1 · C.2Tiers come from one place only, the tiers declaration. The watch list loses its tier column and stays a dependency description.read-tiers moves to a seam of its own, bound once.
  2. 15What happens when two tiers name one identity?13 · 14 · 1That dependency is reported unread, "named by two tiers", and both tiers stay due. Every other dependency is reported as usual. headwater never picks.A new clause beside 13.
  3. 16The default tier's cadence when a tiers file exists; can a tier name identities by pattern?41 · C.2The tiers declaration may set the default's cadence, seven days when it does not. A tier may name identities by prefix; an exact name beats a pattern, and two overlapping patterns are question 15.41 and C.2.
  4. 17Where does a declaration go whose identity cannot be read?1 · 13 · 16At the top of every answer. It makes no tier due: scanning again cannot fix it, and changing the repository can.1 says where.
  5. 18The vocabulary's due and clause 16 disagree after an incomplete scan of a named tier.contradiction15 · 16A tier is due when its cadence has passed since its last complete scan, when its newest scan was incomplete, or when it was never scanned.Rewrite due.
  6. 19A dependency no source can ever read keeps its tier due for ever.15 · 16 · 51One no bound source knows is reported "no source knows it" and does not count against completeness. A source that fails does, until it answers.Rewrite complete; a new status.

Acknowledgements, briefs and notes

  1. 24Who may acknowledge, and how does headwater know who?20 · 24 · actorsOnly by an explicit request that names who gives it, the git identity by default. headwater records the name and does not authenticate it. A recorder never acknowledges.Rewrite 20; the operator's row.
  2. 25Can an acknowledgement be undone, or conflict with another?20 · 21 · 24A later acknowledgement may withdraw an earlier one, and all stay readable. The latest for a release wins. A skip comes back only when a newer release that is not withdrawn is listed.A new clause beside 21.
  3. 26What does a brief cover, and what of a release no report holds?25 · vocabularyThe target's notes and the notes of every release between the pin and the target, since a fixer crossing several releases needs each breaking change. A release no report holds, acknowledgements set aside, is refused.Rewrite brief and 25.
  4. 27What "part" of notes may an asker take, and what is the way to read the whole?12 · 17 · 25The first N bytes, cut back to a line's end. The way to the whole is a brief, which may reach the notes source.12.
