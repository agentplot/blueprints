Boomdrive Work Lifecycle

Only the runner is installed to keep running. sluice starts its own host process when work arrives and stops it when none is left.

Runner Flume Agent sluice GitHub

One unit of work is a using block

Flume holds the place from launch to teardown. sluice decides the outcome and calls nothing; Flume reads it and acts.

Who runs each step

Only the runner keeps running. Every other bar or dot below is a process that starts for its event and ends.

A queue runs where its branch lives

Units land on a bolt on the host. The bolt lands on main by a leased push, or through GitHub's queue when main takes pull requests.

sluice alone is still a plain command line

Without a runner or Flume, the same thing happens: the submit starts sluice's host process, which lands the work and exits once nothing is left.

$ sluice submit main     # forms a candidate, starts its checks, returns
$ sluice wait 12         # only if you want to watch it land

Each tool's job

Runner

always running

Takes leased work, keeps the one clone, launches places.

Each pass ends with one flume settle --every: the host's tick.

Flume

per command

Holds a place from launch to teardown.

Reads each place's outcome at the runner's tick. sluice never calls it.

sluice

while work waits

One process per host, started by the first command that needs it, gone when no queue has work. It holds the host's run slots.

GitHub

its own jobs

Takes pull requests in and runs the queue of a branch that accepts them.

Nix flake

one service

Installs the family and starts the runner. Nothing else.

What changes

Changes in sluice

  • The first sluice command that needs it starts one sluice process for the host. Every queue on the host runs inside it on its own task, and it exits when no queue has work and nobody is watching.
  • Every other command talks to it over a socket. A submit adds its entry and returns.
  • It holds the host's run slots in one place, queued work before agents' own runs.
  • If it dies, nothing is lost: the records are on disk, and the next sluice command starts it again.

Stays

  • sluice starts no other program. Flume, timber and anything else read what sluice decided.
  • sluice submit, and sluice wait if you want to watch.

Goes

  • sluice run and record 0092's host driver
  • One service per repository
  • Counting the host's runs with lock files
  • Taking pull requests in on a host, and the intake mark
