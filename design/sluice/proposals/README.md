# Proposals

Drafted clauses awaiting the operator's ruling. A proposal is ratified by
moving its numbered clauses into `../requirements.md`; until then the
statement stands as written and nothing here binds a model.

| file | proposes | drafted |
|---|---|---|
| `pull-requests-1.md` | a branch on a forge, worked through pull requests, on any deployment and with any executor: the round fetches the branch and lands by a leased push (C.4 pushed refs, unchanged); a pull request is a submission's page, waits while a draft or while a condition the branch's policy names does not hold (an approving review, another system's check on its head), and is submitted only then; a forecast is posted on every waiting request; requests from forks are never submitted. **Adds a pull request driver (C.5) and the policy's `remote` and `pull_requests` (C.7); rewrites the non-goal on outside contributors; adds S21–S24** | 2026-10-14 |
| `session-runs-1.md` | a session's own checks, run in its own place before it submits, under the contract sluice gives a candidate's place: counted against the host's bound, candidates first; ports the policy names, held by the place across runs; the executor's limits; a release the session or its driver asks for, never run between iterations, and run by `wt submit` before worktrunk removes the worktree; a run in a place holding exactly its head recorded under its keys, so a bolt branch replays it; `sluice exec --remote` sends the run to the fleet's executors on a pushed revision. **Proposes 89–97, one glossary entry and S25–S29; adds a session worktree row to C.1 and a session run driver to C.5; the host's setting gains a share for sessions' runs** | 2026-10-14 |
| `previews-1.md` | a running copy of a revision a branch has landed, for a person to click through: a place sluice makes at the revision the caller names, equipped as a candidate's, in which the policy's preview command brings up the repository's stack on its fakes and hands it off; a name per port given as a port is, one flat label unique on the host, and addresses from the policy's templates; one preview per revision whichever branch asked, asking again gives it back; what it brings up read from the previewed revision, what it may use and reach from the branch now; waiting for room in the bound as a session run does; released only when asked, or when its place is gone or its command failed, a failed one kept listed with its output; it decides nothing and counts only while its command runs; a section for the caller on landing cards, reconciliation, and when a real environment from a delivery tool is wanted instead. **Proposes 98–103, one glossary entry and S30–S35; adds a preview row to C.1 and C.5 and `[preview]` to C.7; adds a non-goal on deploying to real environments** | 2026-10-14 |
| `could-not-run-1.md` | a run that did not judge its check: the program could not start, the check exited as the policy's `not_run` says it could not run here, or the host failed the readiness the repository declares after the run; such a run has no outcome (60), is recorded with why and never under its key, blames no entry and runs again, up to a bound after which the candidate reads not passed; a host that fails readiness before a run is refused it (84); an operator may set aside a recorded run whose cause nobody declared. **Proposes 114–116, amends the glossary's *check* and 84, and adds S43–S44; adds `ready` and `not_run` to C.7's `[tests]` and a set-aside record to C.6** | 2026-10-19 |
